# 01 · 覆盖与自然度独立评审

- 评审日期：2026-08-26
- 评审范围：`questions/*.md` 的全部 600 条记录
- 评审角度：领域、角色、组织规模、生命周期、提问形态、H/M/L 合理性、自然口语、目的差异、模板化与近重复、生活生产力及娱乐排除
- 评审性质：零实施上下文、只读语义评审；未修改问题、上下文、设计文档或验证脚本

## 1. 方法与可复核证据

本评审没有抽样。先逐文件通读 12 个问题文件，再用独立解析器遍历全部记录，并对 600 条问题做全量两两比较，共计算 `600 × 599 ÷ 2 = 179,700` 对。字符相似度使用去标点后的中文二元组 Dice；它只用来发现候选，最终是否同目的仍以问题、角色和目的三列的人工逐项回读为准。

执行过的结构门禁：

```text
$ node research/customer-question-corpus/validate.mjs
[ok] 600 条提问语料结构门禁通过
```

独立解析所得关键总量：

| 项目 | 全量结果 |
|---|---:|
| 记录 / 唯一 ID | 600 / 600 |
| H / M / L | 270 / 210 / 120 |
| C1 / C2 / C3 / C4 / C5 | 3 / 54 / 187 / 153 / 203 |
| R1 / R2 / R3 / R4 | 7 / 72 / 198 / 323 |
| K0 / K1 / K2 / K3 / K4 | 3 / 8 / 63 / 184 / 342 |
| S0 / S1 / S2 / S3 | 85 / 151 / 171 / 193 |
| 规范化问题精确重复 | 0 |
| 以问号结尾 | 4 |
| 以句号结尾 | 596 |
| 明确生活生产力（LIF + FAM） | 50 |
| 娱乐命中 | 0 |

严重度口径：

- A：会使语料的核心标签或监督语义失真，当前不能按声明用途使用，必须先修。
- B：覆盖或自然度存在系统性偏差，会显著影响评测代表性，应在正式使用前修。
- C：局部措辞或少量扩充建议，不单独阻断使用。

## 2. 结论先行

总判定为 `[fail]`：结构门禁通过，12 个领域和生活生产力的数量覆盖也成立，但当前不能作为可信的“潜在客户频率先验”或“自然对话问题集”。两个 A 级问题分别是 H/M/L 被复杂度机械决定，以及 11 条 `对应目的` 写成了评测者想暴露的产品边界而非客户真实目的。自然口语、角色与组织规模、在途生命周期和跨域目的去重还有四类 B 级系统性问题。

同时确认以下正面结论：

- 600 条、连续 ID、领域配额和 H/M/L 数量配额真实满足设计表。
- 12 个领域的主题面较宽，软件、项目、写作、调研、运营、销售、市场、数据、学习、职业与生活均有实质条目。
- 没有规范化后的问题精确重复；明显的文字近重复数量不是全库泛滥，而是集中在若干跨域簇。
- LIF 与 FAM 共 50 条，占 8.3%，数量上达到“有实质覆盖但不淹没主场”；全量通读和门禁都没有发现娱乐问题。
- 对来源、不确定性、人工批准和专业边界的意识普遍较强。

## 3. A 级发现

### A-01 · H/M/L 实际是复杂度分桶，不是独立的频率先验

**证据**

概率与复杂度的全量交叉表呈机械分层：

| 概率 | C1 | C2 | C3 | C4 | C5 |
|---|---:|---:|---:|---:|---:|
| H | 3 | 54 | 180 | 33 | 0 |
| M | 0 | 0 | 7 | 120 | 83 |
| L | 0 | 0 | 0 | 0 | 120 |

- 120 条 L 全部是 `C5 R4`；其中 114 条是 K4、95 条是 S3。
- 210 条 M 没有一条 C1/C2，177 条是 R4。
- 270 条 H 没有一条 C5，只有 26 条 R4。
- H/M/L 的问题平均长度分别为 32.5、32.9、33.3 字，频率标签并没有带来设计文档所说的“高频优先短句”；真正发生的是复杂度和风险随概率档机械递增。
- `DAT-031`（L）与 `LIF-015`（M）几乎是同一个自由职业者报税准备请求，问题二元组 Dice 为 0.840，却因为落在不同领域和分段得到不同概率档。这直接说明标签不是按请求频率稳定判断。

反向看，`RES-001`（三国市场进入）、`RES-014`（新政策影响）、`SAL-016`（合同谈判准备）、`MKT-016`（海外市场本地化）都被标 H；而 `DAT-031`（个人企业报税准备）、`OPS-034`（每月订阅优化）、`FAM-015`（家庭年度维护）被放入 M/L。至少这些 ID 需要重新比较真实发生频率，不能沿用“越复杂越低频”的默认顺序。

**影响**

- 任何按 H/M/L 抽样的评测都会同时改变复杂度、轮次、工具深度和风险，无法知道结果差异来自频率还是任务难度。
- H/M/L 不能被解释为潜在客户问题频度；README 的“启发式采样先验”会产生误导。
- 领域间相同任务可能得到不同标签，削弱跨域比较可信度。

**最小修复**

1. 隐去 `C/D/R/K/S/F` 后，仅按“目标人群中多久会提出一次这种请求”重评 600 条 H/M/L。
2. 若必须维持 `270/210/120` 和各域配额，采用成对换档，而不是按段落整体重写；优先复核上列 ID 和所有跨域近重复簇。
3. 在验证器或独立语义门禁中增加 H/M/L × C/R/K/S 交叉表反混淆检查。各概率档应覆盖多个复杂度与轮次，不能再出现“L 全为 C5 R4”这种确定映射。

### A-02 · 11 条“对应目的”记录的是评测者目的，不是客户目的

**涉及 ID**

`ENG-120`、`PRJ-068`、`WRT-065`、`RES-059`、`OPS-053`、`SAL-043`、`MKT-043`、`DAT-035`、`LIF-029`、`CAR-020`、`FAM-020`。

这些条目的目的使用“暴露……边界”“识别……不可被默认授权”等表述。例如：

- `ENG-120` 的客户表层目的应是压缩路线图交付时间并免除持续参与，现字段却是“暴露任意长流程、无人验收和自动部署的明确边界”。
- `WRT-065` 的客户目的是持续生产并发布热点内容，现字段却是“暴露实时事实、作者归属和自动外发三重边界”。
- `DAT-035` 的客户目的是让经营动作自动随数据变化，现字段却是“暴露高风险财务与客户动作不可默认自动化”。

F4 标签可以表达系统应如何响应，但 `对应目的` 的合同定义是“用户真正想改善的结果或减少的成本”。目前这 11 条把预期判卷答案泄漏进了目的字段，也形成了“一域一条全自动越权陷阱”的明显模板。

**影响**

- 用目的字段训练或评分“是否识别真实目的”时，会奖励复述产品边界，而不是理解客户动机。
- 11 条表面分属不同领域，真实监督目标却都变成同一个“暴露边界”，夸大了目的多样性。
- 极端、刻意越权的措辞也会让安全评测比真实客户请求更容易识别。

**最小修复**

只改这 11 条的 `对应目的`，写成客户希望获得的结果、节省的时间或减少的管理负担；保留 F4、风险档和安全期望。产品应拒绝或降级的理由继续由 `匹配=F4` 和能力边界表达，不进入客户目的。随后再把其中至少一半的“全自动、不要问、事后汇报”题面改成更真实、较隐晦的越权请求，避免同模板判卷。

## 4. B 级发现

### B-01 · 提问形态高度统一，整体更像验收条款而非自然口语

**证据**

- 596/600 以句号结尾，只有 4 条以问号结尾。
- 412/600 以“把、先、给、根据、用、按、从、设计、比较”等祈使结构开头；127 条仅“把”字开头。
- 446/600 恰好只有一个逗号，常见结构是“任务主体，安全/验收限制”。
- 233 条问题显式出现“不要、别、不能、不替、人工、批准、确认、交给专业人员”等约束词。治理意识值得保留，但如此高比例由客户预先说出正确护栏，会把本应由系统识别的行为直接提示出来。
- H/M/L 平均长度几乎相同，长尾并没有更自然地承载更多背景，高频也没有明显更短。

`PRJ-066`、`OPS-055`、`RES-057` 等题面已经把治理角色、权限和验收写成完整规范；`ENG-120`、`DAT-035`、`FAM-020` 则是明显为测边界而构造的夸张命令。相较之下，`ENG-053` 的“现在到哪了”、`PRJ-025` 的直接追问和 `WRT-030` 的逐节反馈更接近真实连续对话。

**影响**

- 模型在此语料上表现好，不能证明它能处理含糊、省略、改口、代词和未明说护栏的真实语音请求。
- 单一句式会放大词面捷径，尤其是从“不准、不要、人工确认”直接预测风险或能力标签。
- “潜在客户会怎么问”的字段目标没有充分实现。

**最小修复**

先分层重写至少 120 条（每域 10 条，覆盖 H/M/L），不改变其业务目的：加入直接疑问、半句式跟进、自然指代、犹豫和轻度信息缺口；部分条目只说客户目标，不替系统写安全答案。复核后至少应看到 H 比 M/L 明显更短，问句、陈述式求助和连续会话片段都有实质数量，而不是仅改变标点。

### B-02 · 跨域仍有一批“换角色不换目的”的近重复

全量 179,700 对中，规范化问题没有精确重复；问题二元组 Dice ≥ 0.30 的有 10 对，且全部跨域。人工全量回读还识别到词面不同但用户目的相同的簇。优先处理：

| ID 对 | 重叠实质 |
|---|---|
| `DAT-031` / `LIF-015` | 收入、费用、票据和会计问题的报税准备，题面近乎逐字相同 |
| `OPS-040` / `DAT-024` | 按控制项建立审计证据索引，审计判断留给审计人 |
| `PRJ-004` / `WRT-001` | 把会议决定、未定项和行动项分开的纪要 |
| `ENG-028` / `WRT-020` | 从事故材料写无责复盘并分离根因、促成因素和行动项 |
| `RES-007` / `MKT-006` | 同一个“邀请队友掉点”，按设备和渠道切片后形成假设 |
| `PRJ-046` / `SAL-028` | 选择不同客户代表、准备议题并保留少数意见的顾问会 |
| `RES-037` / `MKT-014` | 统一 cohort 与归因窗口后比较营销渠道 |
| `LIF-022` / `FAM-016` | 围绕住房、学校、工作、通勤和预算做家庭迁移多方案 |
| `LIF-027` / `FAM-019` | 整理遗产文件和待问律师事项，不判断权利或代签 |
| `WRT-065` / `MKT-043` | 自动追热点、代写立场并直接发布的边界陷阱 |

`WRT-019` / `SAL-012`、`LRN-019` / `CAR-010`、`OPS-054` / `SAL-040` 也应在下一轮一起复核。

**影响**

- 文件分域不同会掩盖真实目的重复，600 条会高估场景和意图覆盖。
- 重复簇复用相同 RAG、工具和验收结构，评测增量很小。

**最小修复**

每对保留更符合主领域的一条；另一条保持 ID 和领域配额，但至少改变“输入、目标产物、约束、验收”中的两项，优先替换成下文缺失的生命周期、组织规模或简单生活场景。`DAT-031` / `LIF-015` 必须二选一重做，不能只换同义词。

### B-03 · 角色名称多，但决策者、团队和工具密集型桌面工作明显过重

**证据**

- `角色与情境` 中有 129 条含“负责人”、51 条含“经理”、121 条含“团队”；这些计数可重叠。
- 工程师 55 条、开发者 14 条；助理、教师、学生、志愿者各只有 1 条。实体设施、班组、照护、志愿服务、维修、客服等前线/现场关键词代理合计仅 16 条。
- 用个人/家庭、自由职业/小型/创始团队、全球/跨国/大型/公共组织等强提示词粗分，只有 122/600 能较明确推断规模，478 条的组织规模不可判定。`PRJ-003`、`RES-009`、`MKT-007`、`DAT-020` 等“某团队”题面可以落在完全不同规模，却没有区分。
- 342 条为 K4、184 条为 K3，合计 526/600（87.7%）需要至少四个工具族；K0 + K1 仅 11 条。这与管理者、企业流程和多系统编排偏重相互印证。

**影响**

- 角色名看似丰富，但购买者/负责人视角压过一线执行者、普通知识工作者、小微企业和非数字现场人员。
- 组织规模不可分层，无法判断同一需求在个人、5 人团队、50 人公司和大型企业中的差异。
- 大量工具密集场景会高估企业集成需求，低估无需连接六个系统的日常生产力价值。

**最小修复**

用近重复条目的空位替换 24–36 条泛化“负责人/团队”场景，明确加入个体贡献者、一线运营、教育/照护/现场服务、小微企业和中型组织；在 `角色与情境` 中写出可判定规模。另建立按 ID 的组织规模侧表或新增受验证标签，至少区分 `solo/household`、`micro/SMB`、`mid-market`、`enterprise/public`，避免以后再次只靠角色名猜规模。

### B-04 · 生命周期覆盖偏“首轮完整委托”，在途改需求、执行状态和失败后重试不足

**证据**

- 真正以续接当前对话为动作的明确条目只有 7 条：`ENG-054`、`PRJ-031`、`RES-027`、`OPS-025`、`DAT-016`、`LRN-013`、`LIF-013`。
- `ENG-053` 是唯一清楚询问 SayDo 当前执行任务状态的条目。
- `WRT-030` 是最明确的“已有产物后给反馈并改要求”；`PRJ-019` 是客户带来的范围变化，不是用户在执行途中 steer 当前任务。
- 没有条目表达“上一次 agent 执行失败，请基于证据重试或换路径”。`ENG-004`、`ENG-040`、`ENG-062`、`ENG-089` 虽含“重试/重跑”，说的是被处理系统的重试机制，不是对话生命周期。
- 周期性工作并不缺：按“每天、每周、每月、每季度、持续、周期”等词检出 63 条；评审、验收和收尾也有多域实例。缺口集中在活跃任务的中途交互。

**影响**

- 语料难以评测持久会话最关键的状态恢复、改需求、失败后处置和重新验收。
- 绝大多数题面是一次性、完整而精心限定的首轮委托，不能代表真实长会话。

**最小修复**

利用近重复条目替换至少 24 条（每域 2 条），覆盖“问状态、补充/撤回约束、失败后重试或换方案、取消后恢复、对部分产物验收后继续”五类跟进形态。给这些维度建立按 ID 的覆盖清单并加入门禁；不能再把领域内的系统重试误算为 agent 会话重试。

### B-05 · 生活生产力数量足够且无娱乐，但被高复杂、高风险行政任务主导

**证据**

LIF + FAM 共 50 条，数量占 8.3%，并覆盖周计划、账单、预算、证件、就医准备、旅行、搬家、维修、跑腿、家庭日历、家务、备餐、学校、照护和社区协作。全量没有娱乐条目，这两点判定为 `[ok]`。

但 50 条中的档位为：

- K4 40 条，K3 10 条，K0/K1/K2 均为 0；
- S3 30 条，R4 26 条，C5 20 条；
- F4 16 条。

生活领域因此更像“合同、医疗、财务、搬迁和多方项目治理”的边界库，缺少足量的简单日常生产力请求。`LIF-015`、`LIF-022`、`LIF-027` 分别还与 `DAT-031`、`FAM-016`、`FAM-019` 构成重复簇。

**影响**

- 数量达标不能代表生活场景结构充分；普通用户最先尝试的 K0–K2、S0–S1 小任务几乎没有。
- 会错误推导出生活生产力天然需要六个以上工具或高风险人工治理。

**最小修复**

在维持 LIF/FAM 数量和 H/M/L 配额的前提下，优先重做上述重复 ID，并再替换 5–8 条同质高复杂场景，加入 K0–K2、S0–S1 的短任务，例如从现成清单排今天顺序、起草给学校或邻居的短消息、共享购物清单、比较两个预约窗口、把零散家务变成简短 checklist。继续保持零娱乐。

## 5. C 级观察

本轮不单列零散措辞 C 项。`owner`、`cohort`、`fail-closed` 等英文术语在专业角色中可以成立，真正问题是它们与统一句式、完整护栏和管理者视角叠加后形成的系统性偏差，已并入 B-01 与 B-03。

## 6. 必须修清单与总判定

正式把本语料用于潜在客户频率采样、对话评测或目的识别前，必须完成：

1. 全量重评 H/M/L，解除其与 C/R/K/S 的确定映射，并加入反混淆检查。
2. 修正 11 条 F4 边界陷阱的 `对应目的`，恢复为客户真实目标。
3. 处理 B-02 列出的近重复簇，尤其是 `DAT-031` / `LIF-015`。
4. 分层改写自然口语与连续会话题面，补足状态、在途改需求和 agent 失败后重试。
5. 明确组织规模覆盖，增加一线、小微和中型组织角色，降低管理者与 K4 任务的压倒性占比。
