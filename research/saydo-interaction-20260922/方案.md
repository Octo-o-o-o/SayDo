### 0.4 第一批：语音末端判断与测量准确性

范围：`pipeline/src/saydo_pipeline/{vad.py,hub_client.py,hf_round.py}`中必要的小改及对应测试；HF确需时才改daemon voice/latency。播放计时已有`index.ts`中`turnIdOfSentence(sentenceId)`归属，默认复用，无需新增console计时字段；只有反例证明必要时才改相关callback。不重新设计HF/PTT状态机，不换ASR/TTS/Brain，不加数据库表。

1. **EOU**：续接标点优先，逗号/中文逗号/顿号仍等待；对终止标点规范化后的连接词判断。测试`然后`、`然后。`、`但是，`、`修改配置、`、问句、完整陈述、中英标识符、否定；原ASR文本字节不变。
2. **TTS归属**：在发起/入队时将sentence与真实源turn固定绑定，回包沿该绑定；系统/回叫句无法确定源turn则标未归属，不能借最近ASR。优先复用已有`s-<turnId>-<i>`生成/解析路径，使用项目已有解析器或明确校验，不猜任意ID。`native.reply`的turnId不会自动传入`tts.say`，不能当作已有字段使用。同一turn多句只计一次，按turn去重并有界清理；A慢合成/B新轮/A返回的测试必须仍将A的TTS及播放计时记回A。协议若确需加字段，先canonical一致性评审。
3. **HF测量**：先固定“逻辑轮最终端点”的定义，不能拿首个被续说否定的静音边界当最终端点。现collector用daemon到达时间，忽略跨进程atMs；因此在final后补发一条旧vad_end不能复原真实等待时长。优先复用hfRoundId/segment身份在实时边界接线；若需要候选端点失效/修订或turn映射，先定义最小合同和评审。另一合法分支是仅采pipeline同钟duration作诊断，产品HF五段仍undeterminable，此分支不得关闭L5。
4. 成功分位数、失败/空/取消/超时/缺段分别报告；样本不足不判SLO；“LLM首token/TTS首字节”的现有近似仍声明，不伪称设备入耳实测。真实数据采集需要用户音频/设备时另列条件，不代造样本。

验收：针对修复前可失败的确定性生产方法测试；现有HF/PTT/quiesce/屏障/旧epoch/乱序套件保持通过；TTS和播放不跨轮；未归属不填0；EOU续说负例不退化。语义评审后在固定候选跑项目required full gate。对于合同分支，review只在影响实现的合同边界一次，其余最终统一验收，不按文件数加审查。

### 0.5 第二批：Codex App Server可运行的受控原型

只实现一个TS本地stdio driver及测试入口，建议`packages/daemon/src/experimental/codex-app-server/`，不装配生产index/后端选择器。原§7机制仍适用，但不从旧代码基线开工。

范围：固定CLI版本与生成schema；initialize/initialized；JSONL分帧、背压和有界缓冲；response/notification/server request分流；自有thread创建/read/resume与turn start/steer/interrupt；expectedTurnId拒过期；拒绝优先的审批、user input与permissions；未决请求清理；发送意图、ACK丢失unknown、不盲目重试。归属按task/run标签、thread/turn、进程世代和测试目录核验。测试批准只用fixture具名一次性权限；真实实例默认不扩权。

验收分层：

不做fork旁问、任意Desktop/TUI attach、跨宿主、网络监听、ACP/Python并行路线、新任务数据库、Hopper恢复。原生completed仍只是后端终态，未来生产接线要接已有verify/settle/outbox；本原型不假装已经完成那条链。

## 5. 首个可实施小批：免手控制链与测量补齐

目标包含 L4 控制链、L5/L13 测量接线与归属，L6 标点作为局部 EOU 回归一起处理；不换 ASR/TTS/Brain/执行后端、不改 WS 词表和 DDL。每项分别关闭：日志替代只能提供诊断，不能关闭 L5/L13。若实现必须改变合同形状，先提交 09/10 的小补丁及一致性评审，再施工。

### 5.1 接线设计

1. 保持 `_run_once` 读循环及时消费 PCM 与控制消息；VAD feed 不等待网络 ASR。采用**单个有界的免手识别 worker**，不是每段一个无界任务。PTT 的 FIFO 链继续独立，模式切换不把两者结果混用。
2. 每个免手候选绑定 connection generation、session、mode generation、utterance revision。只在发送 final 前重核当前绑定；模式/会话切换或断线立即取消、await worker，清理旧 PCM/EOU。只增加进程内状态，是否需要 durable 字段由真正跨重启需求决定。
3. 音频续说立即使先前 EOU 预测失效。**首段 ASR 即使晚返回且句尾完整，只要同一输入期间已有续说，就不得先发 final**；累积当前轮候选，直到当前修订的端点/按钮决定成立，再按录音顺序一次发出。不得并发拼接不同用户轮。
4. `done_speaking` 在读循环中只把当前 revision 封口并入队；**等待已有识别必须在 worker 内进行**，不能留下 `_force_finalize` 的内联等待。仅发一次 final；空/异常路径沿当前 PTT 守恒，免手按当前合同处理，不能照搬空 final 去破坏 daemon FIFO。切 mode 与 disconnect 的取消不声明已执行任务回滚。
5. 设明确资源界限：建议一个识别在途、一个待处理续段槽；原始 PCM 总量上限建议 60s（16k mono PCM16 约 1.92MB）作为待定实现参数。超限不静默截断关键否定、不发半句话去 Brain；清晰降级文本/PTT并停止该轮。若现有消息无法表达此失败，必须先走合同增量，不能借 health 冒充轮次失败。
6. 非阻塞控制链只负责语音生命周期。停播继续走 barge-in/watermark；Agent interrupt、cancelTask 继续走现有具名任务控制。禁止把任何 speech_start 直接转成任务取消。
7. 标点处理局限 EOU 判定视图：先判末尾续接标点，ASCII 逗号、中文逗号、顿号继续视为未完；再针对句号等终止标点规范化后检查连接词。原始 ASR 文本保持不变，不影响确认词法。必须覆盖 `修改配置,`、`修改配置、`、`修改配置，`、`然后。`、`但是，`、`完成了吗？`、完整陈述与否定；不把剥标点变成提前终结回归。

### 5.2 测量设计

- 复用现有 `LatencyCollector` 和 `latency.stage`。在免手候选端点生成稳定 turnId，先发 vad_end，后续 asr_final 使用同一 ID；EOU 延续、取消、模式切换必须有明确废弃语义，不能让未成轮候选污染完成率。
- TTS 必须由实际 `tts.say/sentenceId` 关联原始 turn（daemon 当前使用 `s-<turnId>-<i>`），不能合成返回时查“session 最新 turn”。首块去重按 turn，生命周期有界；对回叫/系统句等不可归入用户轮的 ID 保持未归属，不猜测。补 A 合成挂起、B final 到达、A 合成返回的反例，确认播放端与 TTS 两段都归 A。
- 如果现有事件合同不能表达“候选端点作废”，本批先只记录 pipeline 本地结构化时长用于诊断，并保持产品报表 `undeterminable`；不得为了补齐五段发虚假的 vad_end。本地日志只含身份/duration/结果码，不含音频和转写原文。
- 采用上述日志分支时仅可关闭 L4/L6；L5 继续待合同/接线，L13 只有真实句级绑定与歧义计数到位才关闭。**测量未闭合不得开始带有性能晋级结论的模型试验。**
- 拆开两个口径：① 当前 daemon 到达时间的端点后首响；② 音频样本位置确定的最后有效语音至端点等待。后者在同一录音/同一时钟内计算；不把 pipeline monotonic 和浏览器时钟直接相减。
- 当前 `llm_first_token`/`tts_first_byte` 仍按既有近似注记；实际设备播放另验。失败、空转写、取消、超时、丢段、队列溢出均报告计数/分母，成功轮分位数不冒充全部尝试。
- 现有 SLO：P50≤1500ms、P90≤2500ms、每类≥20 有效样本才可判断；不足为 undeterminable。此 SLO 不自动等于“最后一字到耳朵”的实测指标。

### 5.3 验收与退出

| 检查 | 通过条件 | 失败时 |
|---|---|---|
| 慢 ASR / 控制消息 | 自然端点和 done_speaking 按钮两种入口均挂住识别 Promise/Event，后续 barge_in/voice.mode/PCM 仍可被读循环消费；不用脆弱的微秒断言 | 不进入新模型实验 |
| 续说 / 自我修正 | 首段识别晚回不能越过已到达的续说；顺序、revision 和 final 次数正确 | 保留证据，不放宽用户确认 |
| 断线 / mode / session | 旧任务取消并 await；旧结果零跨会话注入；重复 done 不重复 final | 关闭候选，保持旧版本可回退 |
| 上限 / ASR 异常 | 内存有界；明确失败，不发送被截断命令；PTT 原守恒负例继续通过 | 必要合同缺失时停在设计阶段 |
| 测量 | 真实起止与 turn 对齐；双轮慢 TTS 不串位，系统/回叫不借最近用户轮；缺段/失败如实入计数；未测仍 unknown | 不得补零或生成虚拟 PASS |
| 回归 | pipeline 相关全部测试、daemon voice-hub/latency-report/live-wiring、console voice/barrier/草稿；正式候选按项目 full gate + 独立 reviewer | required gate 未验/RED 不能升级交付 |

候选路径仅在独立 worktree。正式批使用项目有效 policy 和冻结候选验收，运行 `just ci`、Playwright（界面受影响时核关键交互）及 emoji/link/diff 门。无 UI 变更不制作新的演示图。回滚是退回候选代码或保持未部署；若以后部署，切换时先停止新语音入口、排空/取消该代 ASR，保持 task/run 与审计，不声称关闭开关会回滚已发生执行效果。

## 6. Smart Turn 和持续 ASR：满足条件才开

### 6.1 先做 shadow EOU，不同时改 VAD

V0=修好控制链后的同一 EnergyVad/ASR/TTS 基线。V1 只在静音候选时用 Smart Turn 3.2 判断“说完概率”，旁路记录不控制 final；现有 PTT/按钮始终可用。对同一录音按相同帧边界回放，保留本轮全部上下文，仅模型输入取末尾 8s；本轮新语音使旧预测失效。模型失败/超时不生成完成意图，回到明确按钮/原基线并记录故障。

建议初筛样本为 10 类各 4 条共 40 条，每条标注应等待区间、最终端点、关键参数/否定：中文长句、中英路径、长停顿、连接词、自我修正、短附和、明确停播、背景人声、外放回声、超时后续说。优先复用 `e2e/golden/asr-regression.mjs`、`audio-smoke-5.py` 及已有合法音频；现有 ASR 文本样本不能充当带端点标注的真实音频。当前未读取私人音频、未开始真人场次。

先拆调参和冻结验收样本，不能在同一组上调阈值后报泛化。40 条为初筛集合，阈值/重试间隔/最大等待策略必须在验收前冻结；不能把每个 PCM 片段当成独立统计样本。

分两道证据门：

1. **Shadow/离线门**：以人工标注的应等待区间和最终端点评分，比较同录音下候选“会在何时结束”的反事实结果。按录音数报告过早终结、漏终结、最终端点误差、候选等待 P50/P90、超时/失败以及 CPU/RSS；不改实际 final。只有过早终结减少、漏终结不增且等待 P90 不劣化时才值得进入下一步；这只是待采用的初筛规则，不是当前测试结果。由于没有控制执行，授权/错任务/重复执行均为 **not_run**，不能记零或据此声称更安全。
2. **隔离实际链门**：只在独立测试会话启用候选端点，先替身后真实音频/ASR，冻结同等后端和权限。对照最终文本、关键否定/参数及实际任务意图，验证错误授权/错任务/重复效果为零、原有负例继续成立，再看真实首响 SLO。零观测错误只描述样本，不保证总体风险为零。真实模型/真人场次未运行，仍需具名前置条件。

如果改善不稳定、主要瓶颈来自 ASR 网络或维护成本抵消收益，停止该路线；不为了小模型而上线。在线资源预算（目标机 CPU/RSS/最大预测时间）须在下载运行前按目标硬件固定，本轮没有测量就不虚构数值。

### 6.2 持续 ASR 是下一项独立选择

只在端点后的 ASR 上传/识别被测为主要瓶颈时，把 adapter 拆为有界 begin/feed/finish/cancel；partial 仅用于屏幕候选，不进入 Brain/记忆/批准；final 对齐既有轮次。连接中断、转写修订、负向指令、费用按连接/时长计的变化必须验证。先固定 ASR 产品版本/请求合同，不从“支持 WebSocket”推导已支持所有 streaming 模式。

原生双工仅在这些改进后仍有可量化摩擦时，选择 MiniCPM 或 GPT-Live 中一个对照。双工前台可送候选文本和事实摘要，不接管授权；高风险提示仍用可信屏幕或确定性渲染。模型/录音/付费/设备场次分别按项目 owner checkpoint 具名安排。

## 7. PG-07 Codex 最小方案（延期设计，不是第二活动批次）

### 7.1 一种路线和最小 seam

建议先用 TypeScript daemon 本地 stdio 的直接 App Server 客户端，适合现有语言与深度双向需要；先固定本机可测版本，不承诺生产上线。Python SDK helper 作为原型成本过高时的备选，不同时维护；ACP 等有第二 provider 的实际需求再议。现有 BYOA exec 原样保留。

`Tier1Backend.buildArgv/parseLine` 不能承载双向请求；也不应把整个 executor 推倒重写。先在 research/spike 中做进程级 session driver：请求相关联、通知投递、服务器请求响应、终止和资源清理。实验成立后，提 ADR 为 executor 提供一个狭窄的异步 session 适配 seam；Claude/Cursor 仍走原进程实现。是否复用 AgentSpawner 的 handle 需逐签名核对，不能现在假称可直接替换。

首批不做 fork/旁问、跨宿主恢复、任意 Desktop/TUI attach、统一 capability 平台。允许创建的仅是 SayDo 拥有的新测试会话。`thread/read` 只读取；磁盘同 thread ID 不提供运行实例控制权。

### 7.3 效果治理与恢复

- 所有权绑定：本地 task/run ↔ host/account alias/process generation/thread/turn/worktree；审批另绑 native request ID、作用对象、权限、有效期和消费状态。先复用现有 run/receipt，只有真实持久化缺项才提 09 与 additive migration；不在研究阶段预建表。
- 区分 response、notification、server request；未知权限请求拒绝或返回不支持，未知非授权通知可记录版本不兼容并停用受影响能力，不能把所有新增观测事件都当批准。
- 文件写、shell、网络、MCP/插件、子 Agent、扩权逐项建立效果覆盖表。只出现过一个 approval 不证明覆盖完整；无法强制治理的工具关闭。只读 sandbox 也不等于无法读密钥，凭据/环境最小化另验。
- 不把 `turn/start` 的 request ID 当服务端幂等承诺。发送前保存本地意图；响应丢失时先 inspect/reconcile，无法确定就保持 unknown/人工核查，不自动重发、不因重连再次创建任务。
- interrupt 请求与本地取消 durable intent 分开；取消和晚到 completed 竞争仍由现有取消优先处理。原生 completed 只提供后端结束事实，仍走冻结 verify、settle proof、outbox 后才等待验收。
- 进程退出使全部 pending 请求结束为明确失败/unknown；保存无敏感原文的证据与版本，关闭开关不删除未决任务，不自动启动第二控制器。
- BYOA 和执行会话目录/配置/权限/寿命独立；本轮不改现有 cage，也不把会话上下文广播给语音前台。

原型必须覆盖：请求乱序、未知反向方法、拒绝、过期审批、重复消费、ACK 丢失、stale turn、取消/完成竞争、持久化失败、崩溃恢复和原后端回归。fixture 先行；真实隔离 Agent 只在有效 policy、额度/目录范围清晰后运行。无法满足效果策略就延期，不为跑通降低 S3 或 verify。
