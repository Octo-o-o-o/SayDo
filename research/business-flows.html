图 0 · 落地分工：VoiceLoop 语音前脑 + Hopper 执行后端（v1.13，待战略确认）

三本地项目综合结论：VoiceLoop 只自建「语音前脑」三块独特能力 + 一层缝合，其余下游复用现成（首选 Hopper）。

要点：这修正了主方案 §13 一个盲点——之前"重型后端=OpenClaw(可选)"，但 OpenClaw-Kit 编排正被并入 Hopper，后端终局就是 Hopper。此为待你确认的战略；若确认，下面图 3 的"派发→worktree→执行"即"drop 进 Hopper→Hopper 跑"，回叫即"消费 Hopper 事件"。

图 1 · 系统架构与数据流总览

谁把什么给谁：人↔语音↔Brain↔daemon↔agent，daemon 读写记忆并回叫人。Brain 无状态、agent 原始事件先经摘要再进 Brain。

要点：① Brain 无状态、无直接执行权——副作用全在 daemon，工具返回值是它的全部世界观（语音层可随时重建）。② agent 原始事件流永不直接进 Brain，先经摘要器。③ 记忆是枢纽：daemon 读它拼 Context Pack、写它沉淀产物。

图 2 · 主交互闭环（上半）：对话 → 双维就绪自省 → 决策包 → 拍板

不下指令，聊到 AI 自己判断「知识够 + 需求清」两维都够，才主动给决策包请你拍板。

要点：不过早收敛——聊天阶段允许发散（思路完善），只在两维真的都够时才收敛到决策包。开工由 AI 提议，人只做审阅式轻确认（看 Demo 判断，而非凭空表达需求）。

图 3 · 主交互闭环（下半）：派发 → 后台执行 → 回叫 → 验收交活

拍板「开工」后语音会话可挂起、你走开；任务后台跑，完成/卡住主动叫你，验收后合并。

要点：语音会话与开发任务生命周期解耦（会话挂起省钱、任务后台跑）。改需求 Tier1(Claude) 走 steer 流式注入、Tier2(Codex/Cursor) 走 kill_and_resume。非 coding 类型无 merging/verify，收尾改为「内容评审」。

图 4 · 任务生命周期状态机

任务卡从「对话沉淀的草稿」到「交活」的完整状态；learning 为准备知识时的透明等待态。

要点：非 coding 类型无 merging/verify（走内容评审收尾）。启动对账：daemon 重启后，状态 running 但进程不在的任务→标 interrupted→resume 恢复。

图 5 · 三条对话路径 × 分层记忆 × Context Pack 装配

与「ChatGPT 新窗口」的分水岭：持久知识库(L0/L1/L2) ≠ 每次拼接的 Context Pack。

要点：全新项目必须先奠基建 L1，否则等于零上下文开聊（= ChatGPT 新窗口）。知识库随对话生长（写 L2）并定期提炼（进 L1）；代码类知识用 git diff 增量刷新，对话/调研类靠时间衰减+用户纠正（记忆生命周期治理是 §15 已识别的待补项）。

图 6 · 回叫升级链 + 审批风险分级

什么事件值得打扰、用哪个通道；语音是弱认证通道，只能批到中等风险。

要点：拦截 ≠ 叫人（危险动作先让 agent 换路，反复撞墙才升级人，降回叫频率）；审批中断点落盘可恢复（daemon 重启不丢，§15 缺口 G2）；电话层可 DTMF 闭环确认。

图 7 · 部署拓扑：移动沟通端 × 桌面/服务端执行（v1.13，落地形态）

沟通天然移动、执行天然固定 → 前脑与后端物理跨设备分离。人在手机随时聊，桌面/服务端生产环境实施，结果推回手机。

要点：移动端只做沟通面（语音 I/O / 看 Demo / 拍板 / 审批），重活全在执行端；两者靠安全通道 + 事件流连接，手机断连不影响后端执行——这正是"路上聊、家里的 Mac 做、醒来交活"成立的前提。与竞品成熟形态一致（Happy/Omnara/Cursor iOS/Nimbalyst 都是手机遥控本地 agent）。
