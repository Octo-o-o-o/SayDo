# 87 · 状态对齐实施后独立复核：对外承诺与双语内容

> 复核方式：零上下文只读 subagent。
> 对象：Grok 首轮实施后的未提交工作树，尚未包含本轮回修。
> 结论：`FAIL`，A 2 / B 4；回修后由调度方重新验证。

## A 级

1. Docs 的组件说明使用「无云端依赖 / no cloud dependency」绝对句，但同页又列出第三方 AI、火山豆包语音与 ntfy 推送。建议改为「核心组件本地运行；用户主动启用的第三方服务例外」。
2. 中英隐私页把麦克风音频写成「仅本机处理 / on-device only; never uploaded」，但原生壳把音频交给系统语音识别，iOS 还存在允许联网识别的配置。建议明确「SayDo 不保存音频；设备端或联网由应用 / 系统设置与厂商实现决定」。

## B 级

1. 手机 companion 的能力概述容易把桌面控制面能力泛化到手机。最终文案必须以来源面分权为准：LAN 不裁决 S2/S3，tailnet 最高 S2，S3 回 Mac。
2. 「本地优先」不能写成「绝不出网」。AI 上游、系统 / 浏览器联网语音、桌面云端语音与推送都要在同一段落给出例外。
3. `prompts/75`、`prompts/76` 把 `[ok]` / `[fail]` / `[warn]` 误写成 pictographic 禁项；这与仓库文本状态标记规则冲突。
4. Grok 的 evidence 只记录了沙箱内浏览器失败，未记录调度方后验 Playwright 成功；需要追加独立章节，不能倒填成 Grok 自己的命令门。

## 复核建议

- 对外页优先回修 A 级绝对句。
- 中英文同批同步，并同时更新 Docs 源稿。
- 回修后重新跑零 emoji、静态链接 / fragment、桌面与手机视口、浏览器 console。
