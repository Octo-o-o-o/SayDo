# 最终覆盖与自然度独立评审

- 评审日期：2026-08-26
- 审查对象：`research/customer-question-corpus` 当前 12 个 `questions/*.md` 最终候选、目录说明与 `validate.mjs`
- 审查边界：未读取 `review/` 中任何既有报告，未读取 `research/codex-findings/`、`prompts/` 或实施过程记录；未修改语料、脚本或上下文包
- 唯一写入：本报告

## 1. 总判定

**不通过。**

结构门禁、600 条完整性、领域配额、生活生产力、非娱乐边界、标签反耦合、生命周期类型和输入模式均达到可用水平；但 `需求频率先验` 存在一项 A 级语义问题：统计反耦合成立，不等于 H/M/L 的真实含义成立。当前多组同领域条目出现明显频率倒挂，若按 H/M/L 选择访谈或评测样本，会系统性高估组织级、低发生率场景并低估常见日常请求。

在修正 A-1 之前，不应把本候选称为“最终通过”。如果完全不使用 H/M/L，只把 600 条当作场景库，主体覆盖已经可用；这不等于带频率先验的语料通过。

### 分级口径

- A：阻断最终接受；会改变采样、结论或核心使用方式。
- B：不破坏结构，但会实质影响自然度、去重或覆盖解释，建议在发布前修复。
- C：局部质量或可分析性限制，可带说明进入下一轮。

## 2. 门禁与全量方法

```text

```

结果：exit 0；关键原始输出如下。

```text

"demandPrior": { "H": 270, "M": 210, "L": 120 }
"nearDuplicatePairsAt055": 0
[ok] 600 条提问语料结构、分布、上下文与反耦合门禁通过
```

emoji 门禁最初两次命令形态不正确，均未被当作业务结论：

脚本要求传入文件而不是目录；改为对语料范围内、排除 `review/` 的全部文件传参后成功：

  -exec bash scripts/check-emoji.sh {} +

### 2.2 独立 600 条遍历与两两检查

另用不落盘的 Node 内联审查器独立解析全部表格行，未复用 `validate.mjs` 的记录集合。结果：

```text
records = 600
question files = 12
pairwise comparisons = 179700
normalized exact question duplicates = 0
```

两套全量两两方法均遍历 `600 * 599 / 2 = 179700` 对：

1. 问题文本二元/三元字符 gram，多重集合 Dice；二元 Dice `>= 0.55`、`>= 0.50`、`>= 0.45`、`>= 0.40` 均为 0，二元 Dice 最高为 `SAL-002 / SAL-012 = 0.333`；二元、三元和问题加目的的组合分最高为 `ENG-109 / WRT-042 = 0.280`。
2. 中文词切分加问题/目的字符 gram 的 TF-IDF cosine；`>= 0.40` 为 0，`>= 0.30` 为 3，最高为 `LIF-005 / FAM-003 = 0.354`。

机械阈值没有发现可直接判重的条目，但人工回读高分候选后仍发现三组“输入、判断、输出差异不足”的语义近重复，见 B-2。字符相似度只能做召回，不能替代此裁决。

一次附加统计脚本因输出字段变量名笔误退出：`ReferenceError: everydayLow is not defined`。修正字段名后以相同遍历逻辑重跑 exit 0；本报告没有采用失败运行的任何结论。

## 3. A 级发现

### A-1 H/M/L 统计解耦通过，但语义先验不可信

独立计算 `需求频率先验` 与各标签的 Cramer's V：

| 标签 | Cramer's V |
|---|---:|
| C | 0.0712 |
| D | 0.0644 |
| 现实周期 H0-H4 | 0.0785 |
| R | 0.0686 |
| K | 0.0723 |
| S | 0.1003 |
| F | 0.0878 |

这些值支持“没有被复杂度、时延、轮次、工具、风险或能力档机械决定”。三档也都覆盖全部 C 档及足够多的其他档位。反耦合本身通过。

问题在于，H/M/L 作为“需求发生频率”在同领域内出现多组难以解释的倒挂：

| 领域 | 标 H 的低发生率候选 | 同领域被放到 M/L 的更日常候选 |
|---|---|---|
| 软件与 IT | `ENG-108` 形式化模型检查、`ENG-111` 全公司密钥轮换、`ENG-118` 遗留主机批量集成 | `ENG-007` 依赖安全更新、`ENG-010` 类型错误、`ENG-018` release notes、`ENG-086` 新人 onboarding |
| 项目与产品 | `PRJ-061` AI 旁听客户会、`PRJ-065` 大型软硬件集成、`PRJ-066` 公共部门审计计划 | `PRJ-002` PRD 样张、`PRJ-018` 轻 Demo、`PRJ-028` 发布 readiness |
| 运营 | `OPS-037` 500 人现场活动、`OPS-046` 并购运营整合、`OPS-052` 灾后恢复 | `OPS-010` 尾款发票、`OPS-022` SOP 现行版本、`OPS-030` SaaS 资产盘点 |
| 市场 | `MKT-039` 大型企业 rebrand、`MKT-045` 全国公益倡议 | `MKT-002` 落地页首屏改写、`MKT-006` 注册邮件效果验证 |
| 学习 | `LRN-030` 一年期研究人才培养 | `LRN-002` 针对真实问题讲解概念并出题 |
| 生活 | `LIF-025` 一年期海外移居 | `LIF-004` 个人订阅续费、`LIF-010` 周末跑腿 |
| 职业 | `CAR-017` 高管六个月职业转换 | `CAR-001` 简历针对性修改、`CAR-004` offer 比较 |
| 家庭 | `FAM-011` 多子女长期照护协调 | `FAM-002` 每周家务分工 |

最直接的内部对照是 `ENG-020` 与 `ENG-007`：两者都要求先判断漏洞/安全更新是否可达，再决定是否升级，前者标 H、后者标 L。角色规模可以影响总体人群，但不足以解释同一动作跨越 H 到 L。`PRJ-039` 与 `PRJ-062` 都是持续项目组合治理，也分别标 H 与 L。

启发式扫描还找到 17 条 H 命中“全球、跨国、大型、公共、并购、一年、形式化、灾难”等低发生率线索；这不是市场统计，但与上面的逐条语义对照方向一致。当前设计似乎优先保证了每个复杂度层的固定配额，代价是频率标签被迫穿过明显的场景常识。

影响：README 建议按 H/M/L 使用和抽样。一旦下游把 H 当高频，样本优先级会被误导；免责声明“非实测概率”不能修复同一语料内部的语义倒挂。

修复要求：

1. 先写一份可逐条判定的频率 rubric，至少明确“目标人群规模、单个用户发生频率、任务触发概率”冲突时谁优先。
2. 在每个领域内部对 600 条重新排序，再定阈值；固定 45/35/20 配额只能作上限或目标，不能反向覆盖语义判断。
3. 对同主题簇做成对校准，至少覆盖上述 ID；若无法为 H/M/L 提供稳定解释，应改名为“采样层”而不是“需求频率先验”。
4. 回修后重新输出反耦合矩阵；语义合理和统计解耦必须同时成立。

## 4. B 级发现

### B-1 自然口语总体可读，但安全/治理约束写得过于整齐

独立全量统计：

| 信号 | 条数 | 占比 |
|---|---:|---:|
| 以“把”开头 | 99 | 16.5% |
| 含“先” | 165 | 27.5% |
| 含“别/不要/不能/不许/禁止” | 157 | 26.2% |
| 含“只” | 77 | 12.8% |
| 含“确认” | 52 | 8.7% |
| 含“证据” | 60 | 10.0% |
| 含 `owner` | 30 | 5.0% |
| 含选定治理/产品英文术语 | 41 | 6.8% |
| 以问号结束 | 25 | 4.2% |
| 任意位置含问号 | 70 | 11.7% |

命令句本身是自然的人机交互形态，问号少不能单独判错。语料也有很好的真实口语，例如 `ENG-004` 的“本地过、CI 挂”、`PRJ-004` 的“会刚散，我怕……”、`LIF-015` 的“怎么排最稳”、`CAR-004` 的“越比越乱”。

但大量条目同时给出输入、方法、验收、权限和禁止动作，语气更像测试作者预埋 oracle，而不是客户自然首句。例如：

- `ENG-109`：“从 schema 生成 SDK、文档和契约测试，任何手写分叉都在 CI 拒绝。”
- `WRT-047`：“旧版本保留 supersede 关系，冲突处找 owner 确认。”
- `PRJ-060`：“季度 outcome”“继续或停止的门”。
- `DAT-028`：“异常先 quarantine 并通知 owner”。
- `OPS-040`：直接规定“按控制项建立证据索引，充分性由审计人判断”。

这些句子作为治理测试很有价值，但若全部放在同一个“潜在客户怎么问”的层，会高估客户主动表达验收门和权限边界的能力，也会低估系统主动澄清的难度。

修复建议：保留治理含义，但将一部分约束移到后续 fixture/oracle；尤其对 H 档，用更短、更省略、更含指代的首句，要求系统追问得到验收和授权。建议至少按领域和 H/M/L 分层回读全部 600 条，而不是只改最长句。

### B-2 三组语义近重复未满足“两项差异”标准

高分候选回读结论：

| ID 对 | 输入 | 判断/决策 | 输出或外部效果 | 结论 |
|---|---|---|---|---|
| `PRJ-021 / RES-004` | 都是同一批访谈原话 | 都要求区分原话、观察、推断并防止小样本外推 | 一个写“分层”，一个找“共同模式/反例” | 差异不足，建议合并或显著改写其一 |
| `ENG-086 / WRT-021` | 都是新成员第一周与隐性知识 | 都要求找可确认知识 | 可跟踪 onboarding 与第一周指南高度重叠 | 差异不足，建议合并或改变验收/输入 |
| `RES-019 / LRN-001` | 都是考试大纲、错题、可用时间 | 都按权重决定学习优先级 | “最该补三块”与“八周计划”仅输出粒度不同 | 至少再改变输入或验收，否则合并 |

以下高分对经回读可保留，因为至少两项不同：

- `LIF-005 / FAM-003`：本人复诊时间线与冲突清单，对比家属的材料、接送和照护协作。
- `OPS-006 / LIF-004`：组织席位、owner 和续费窗口，对比个人使用情况、建议与不取消约束。
- `OPS-032 / DAT-025`：真实劳动规则下排具体班次，对比产生不确定的容量区间。
- `ENG-117 / RES-060`：区域故障恢复演练，对比市场/监管/现金流战略冲击演练。
- `SAL-002 / SAL-012`：初次通话后确认发送，对比客户改优先级后的旧约束撤销；生命周期差异成立，但建议在索引中显式标为“变更后重建承诺”。

`LIF-025 / CAR-019` 处于边界：家庭移居与海外求职输入有差异，但输出都接近跨国迁移时间线。若两条都保留，建议给其中一条增加明确不同的验收物。

## 5. C 级发现与限制

### C-1 “对应目的”完整且唯一，但少量仍是产物改写

600 条目的均非空，规范化后无精确重复；目的字段多数能说明减少的成本、避免的风险或支持的决定。对目的文本再次做 179700 对二元 gram 检查，只有 3 对达到 Dice `>= 0.60`，主要是“守住专业边界”等共同措辞，不构成目的重复。

启发式规则识别出 41 条（6.8%）目的更像输出物或解决方案，而不是更深的客户结果，例如 `ENG-109`“建立合同单源与机械同步”、`PRJ-028`“形成 fail-closed 的门禁视图”、`WRT-006`“产出……技术文档”。建议将这些目的再追问一层“为什么”，避免问题与目的同义复述。

### C-2 角色文本很丰富，但组织规模无法稳定分层

- 600 条中有 599 个不同的角色字符串，说明场景丰富，也说明该字段几乎完全是自由文本。
- 以“负责人、经理、总监、主管、CTO/CIO/COO、创始人、架构师”等保守规则命中 209 条；以工程师、开发者、分析师、专员、助理、管理员、学习者、个人、家庭等规则命中 184 条。两组有语义覆盖但并非互斥完整分类。
- 项目领域有 58/70 条命中领导/管理角色；一线、执行与低数字熟练度虽然存在，但总体仍偏管理者和知识工作者。
- 角色文本中只有 49/600 条（8.2%）带明确的规模线索，如个体、小型、中型、大型、全球、跨国、公共或具体人数。现有代表 ID 足以证明“有覆盖”，不足以支持按组织规模做完整比例分析。

如果后续需要按组织规模或角色层级抽样，应新增规范化的 `org_size`、`role_level` 或独立索引；不要从 599 种自由文本临时猜分类。

## 7. 剩余限制

1. 即使完成 A-1，H/M/L 仍是专家先验，没有访谈或遥测校准；不得表述成客户概率。
2. `LIVE` 出现在 478/600 条中，真实回放高度依赖登录态、新鲜数据与外部系统；冻结语料本身不能提供完整可复现性。
3. 生命周期有首句覆盖，但没有多轮 transcript、授权状态和验收 oracle；不能据此声称状态机评测已经完整。
4. 语料明显偏知识工作、数字系统与管理协作；制造、公共服务、教育、照护等有代表条目，但不是行业人口样本。
5. 自然度、角色与输出家族的数量来自透明的启发式正则，只用于发现偏差，不能冒充人工标注。

## 8. 重新验收条件

重新提交前至少满足：

1. A-1 所列同领域频率倒挂完成全量回标或明确改名，并保留逐条可解释依据。
2. B-1 对 H/M/L 分层回读，降低“首句已自带完整 oracle”的比例，同时保留安全测试价值。
3. B-2 三组近重复完成合并或形成至少两项可判定差异，边界组补强验收物。
4. 重新运行 `validate.mjs`、语料范围 emoji 门禁和 179700 对近重复检查。

达到以上条件后，可再做一次零上下文最终评审。
