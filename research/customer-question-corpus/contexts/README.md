# 合成上下文包索引

所有材料均为本语料专用的虚构数据，不对应真实公司、客户或个人。每个包先读 `manifest.md`，再读来源文件；manifest 通过 `as_of`、`valid_until`、`claim_scope`、`supported_questions` 和 `unsupported_scope` 说明新鲜度、按 claim 类型的权威规则与题目白名单。

只有问题行明确列出的 `CTX-xx` 才加载对应包。`USER` 表示材料由潜在客户现场提供，`LIVE` 表示还要读取当前 repo、系统、connector 或 Web；它们都不是本目录缺失文件的占位说法。冻结 fixture 可以做离线来源治理回放，但不能冒充现实世界现势。

每个 manifest 中的 `corpus:required-claims` 区块由 `rebuild.mjs` 生成，不手改。每一行都包含：

- 问题 ID；
- 回放时 fixture 必须支撑的事实；
- 可以提供这些事实的具体来源文件；
- 题目还需要的 `USER` 或 `LIVE` 输入，若无则为 `-`。

白名单回答“这道题能否使用这个包”，required claims 回答“这个包究竟支撑哪部分”。若问题需要当前仓库、当前账户状态、现行法规、实时价格或用户私人材料，fixture 只提供冻结背景，不能把相应补充输入写成已经存在。

manifest 还登记 `fixture_sources_digest` 与 `required_claims_digest`。前者覆盖来源文件名及完整内容，后者覆盖逐题合同表；验证器会重算两者，因此空白来源、未登记改写或合同表漂移会被拒绝。摘要只能证明构成和内容未漂移，不能证明一句 claim 在语义上真的由该来源支撑；所有仅依赖 CTX 的问题都必须另有显式逐题事实合同，并接受独立语义复核。
