01

准备一个 AI 供给

SayDo 本身是本地协作服务；对话与执行所需的 AI，使用你选择的供给。先备好其中一种，安装后才能开始聊天。

电脑上已安装并登录 Codex、Claude Code 或 Cursor 等支持的 CLI，可以复用它的模型供给。下面是登录命令，不是安装命令；请先确认对应 CLI 已经可用。

Codexcodex login
Claude Codeclaude auth login
Cursorcursor-agent login

准备服务商提供的 API Key、接口地址与模型名称。安装后，在本机控制台的资源画像向导或设置里选择相应 API 方案；高级配置支持 OpenAI 兼容接口。

Key 只在本机控制台填写。本官网没有 Key 输入框，也不会收集你的凭据。

先分清两件事：对话供给负责和你聊，执行器负责真正修改项目。能用 Codex 聊天，不等于 Codex 执行器已经可用；执行边界见下方第 06 步。

SayDo 桌面服务免费、开源；AI 使用受你所选服务商的计费、订阅与额度限制。

02

安装到自己的电脑

选择系统，在该电脑的终端中运行下面的命令。安装脚本会准备所需的 Node.js 22，并下载固定版本包、校验 SHA-256；无需先安装 Node.js，也无需克隆源码。

macOS / Terminal
curl -fsSL https://saydo.octoooo.com/install.sh | sh

这条命令会下载并运行安装脚本。默认安装在用户目录内，不替换系统 Node；你也可以先查看脚本内容，再决定是否执行。

先查看安装脚本
安装包包含：本地 daemon + Web 控制台。不包含：完整 Python 语音管线、macOS 常驻部署，以及第三方 AI 订阅。先完成文字对话，不需要这些额外步骤。
已装 Node.js 22？也可以使用固定版本包。

需要已有 Node.js 22 和 npm。下面是官网镜像上的固定版本包；依赖安装仍可能需要网络，不是完整离线安装包。

macOS / Windows / Linux · npm
npm install --global https://dl.saydo.octoooo.com/releases/v0.1.0-rc.13/saydo-cli-0.1.0-rc.13.tgz

校验值来自安装脚本，对应下载的 .tgz 文件。

SHA-256: 541193d2289831874cf52ac8ef587a0347d07b95daf802802f4ffb1382e80c22下载固定版本 .tgz
GitHub 下载慢或不可达时怎么办？

一键脚本会先尝试 GitHub Release，失败后自动改用官网镜像，两处使用同一份 SHA-256 校验。访问网页和阅读安装步骤不需要去 GitHub。

网络问题请保留终端中的错误信息。镜像也不可达时，先解决网络连接，不要跳过包校验。

03

打开本地控制台

安装完成后，新开一个终端窗口，运行：

终端
saydo up
TERMINAL启动方式示意 / 非实际日志

$saydo up

本地服务运行 → 浏览器自动打开控制台

保持这个终端窗口开启。当前快速启动是前台运行；按 Ctrl+C 可优雅停止，下次用 saydo up 再启动。

浏览器没有打开，或之后想再次进入控制台？在另一个终端运行：

终端
saydo open
不要直接打开裸端口地址。使用 saydo open 生成带访问凭证的控制台入口。把控制台当成自己的本地工具：不要分享带令牌的地址，也不要把服务暴露到公网。
04

按向导连接模型

首次进入会看到资源画像向导。它检查这台运行服务的电脑上有哪些已安装、已登录的 CLI 或已配置的 API 供给；选择方案，阅读知情确认，再按向导启动。

选择方案自检 1/2按提示重启服务自检 2/2

自检会实际调用你选择的模型，受服务商额度或 API 计费规则影响。CLI 模型响应可能较慢；请看向导状态，避免重复点击。若提示重启，保存配置后按向导操作。

没有可用方案？先在同一台电脑上完成 CLI 登录，或在本机向导里配置 API 供给，再重新检测。仅安装 SayDo 并不会自动获得 AI 账号或额度。
05

聊起第一件事

配置完成后，进入「开口聊」。先打字就可以。第一次，不妨从一件明确的小事开始；不需要自己写出完整实施方案。

我想把这周的事情理一理：周五交产品介绍，还有客户资料要准备。先帮我把要做什么、哪些要我拍板聊清楚。
复制后，粘贴到你电脑上的 SayDo。

接下来，你会做什么

补充它提出的问题，确认这件事的归属。涉及代码项目时，在本机控制台选择对应的本地工作区；让它先理解项目，再讨论计划。

什么才算往前推进

需求与计划对齐后，由你确认这一轮。真正执行还需要可用的执行器；任务返回后看成果与依据，未验证的部分继续确认，而不是把“收到”当“交付”。

06

按需要，再接入更多能力

用语音，把事情聊起来。

语音输入和实时对话，是 Say 的两种方式。快速安装先准备好本地服务与控制台；语音还需要对应的识别、朗读和采集能力。

语音输入：先说出来，再决定怎么发。

按住说话，或把语音转成可编辑的文字。遇到名字、术语或复杂表达，可以先改一改，再确认发送；发送一句话不代表批准执行。

未配置云端时，受支持浏览器可使用系统语音兜底；识别与朗读的可用性取决于浏览器、系统和权限，不等同于完整实时语音管线。

实时语音：连续听说，随时补充。

在完整语音路径中，用免手持对话连续沟通。它回应时，你可以打断、纠正或补充；也可以用“说完了”明确结束一轮，再让它接着说。详细计划与验收依据仍留在屏幕上。

需另外配置 Python 语音管线与语音服务凭据；轻量快速安装包不包含完整管线。实际响应与打断体验依赖设备、网络和语音方案。
01先确认模型供给已连通，文字对话能正常回应。语音不通时，不需要删除项目或重装全部服务。
02在实际 SayDo 控制台允许麦克风与声音播放，确认输入设备。不要在这个官网演示里找录音权限：本页不会请求。
03选择系统语音或配置完整云端语音。完整路径需要语音服务和 Python 管线都可用，不能只填好模型就假定语音已连接。
04运行 saydo doctor 查看 pipeline、ASR/TTS 与下一步提示；从短句开始测试，再尝试连续对话和打断。

07

遇到问题，先看这里

先确认服务、配置和模型是否各自正常。下面的命令只做启动或诊断，不会清空你的数据。

终端说找不到 saydo。

先关闭旧终端、新开窗口，让安装脚本写入的 PATH 生效，再运行 saydo help。仍然找不到时，核对安装是否真正成功；不要反复删除 ~/.saydo，它还存着你的账本与记忆。

终端
saydo help
控制台打不开，或提示凭证失效。

保持 saydo up 所在终端运行，用 saydo open 重新打开带凭证的控制台。不要使用裸的 localhost 地址；也不要复制他人的控制台令牌。

终端
saydo status
saydo open
模型一直在等待，或者自检不通过。

先在服务所在电脑上检查 CLI 是否仍已登录、订阅额度是否可用，或 API Key、地址和模型名称是否正确。用 saydo doctor 查看具体故障与下一步；自检有真实模型调用，不要连续重复提交。

终端
saydo doctor
能打字聊天，但不能语音。

快速安装没有完整语音管线，这不等于文字服务启动失败。先检查浏览器系统语音支持、麦克风权限与输入设备；要用完整云端语音，再按第 06 步配置。诊断出现 voiceReady=false 时，结合管线状态看原因。

用 Codex 聊天没问题，为什么不能执行？

模型供给和执行器不是同一层。对话方案可以复用 Codex 登录态，但当前 Codex 执行器尚未实现，会拒绝启动。请按照完整文档配置当前受支持的执行器，不要把报错当成授权提示而强行绕过。

如何停止，之后还能继续吗？

在运行 saydo up 的终端中按 Ctrl+C 可优雅停止服务。之后重新运行 saydo up。不要为了退出删除数据目录。项目数据主要保存在本机，但你选择的模型和语音服务可能接收处理所需的信息；本地运行不等于所有数据都不出设备。

安装命令、版本与校验值按 2026-09-16 读取的仓库 README、官网安装脚本和 Docs 内容稿整理。官网示意图不是设备检测结果；网页不会在你的电脑上自动运行这些命令。
