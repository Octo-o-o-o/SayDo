THE PROBLEM / 它解决什么

说过的话，不再转头就忘

没有它的时候

HOW / 它怎么做到的

四件事，缺一不可

上面那段对话能成立，靠的是这四条机制。市面上每一块都有成熟单点，但还没人把它们做成同一套闭环。

01

先吃透，再办事

第一次聊一个项目，先读透结构、约定与关键文件，沉淀成持久知识底座——此后每次都带着理解开聊。这是和「新开一个聊天窗口」的分水岭。

02

AI 真的在干活

接上你电脑上已登录的 AI——Codex、Claude Code、Cursor、Gemini CLI、Grok。已订阅哪家用哪家，无需额外付费。

03

人拍板才算数

开工前给决策包三件套；做完说「等你验收」而不是「做完了」。合并、交付，永远你点头才算。

04

跨设备同一本账

手机说话、看进展、点头确认；重活留在你的电脑上，S3 重操作永远只在电脑。沟通是移动的，执行是固定的。

Q&A / 先说清楚它不是什么

你大概想问

你
它用的是哪家的 AI？要我再买一份订阅吗？
说
不用。它接上你电脑上已登录的 AI——Codex、Claude Code、Cursor、Gemini CLI、Grok 等替它对话、思考、评估；动手改代码当前稳定路径是 Cursor Agent，Claude Code 正在最终收口。已订阅哪家用哪家。
你
这是语音输入法吗？
说
不是。它不做「语音转文字再粘贴」，而是先吃透你的项目上下文，把每件事记成一本账，听懂了主动提议开工、自己把事办成。核心竞争力不在用哪个模型，而在上下文工程和人机协作流程。
你
我的对话和项目数据，会传到你们服务器吗？
说
我们没有服务器（上面那张总装图画的就是这个）。不运营任何云端后台，没有账号体系，不埋点。数据保存在你自己的设备上；手机与电脑之间走你自己的局域网或你自行配置的加密组网。
你
手机上能用到什么程度？
说
沟通天然是移动的，执行天然是固定的。手机上说话、看进展、点头确认（审批封顶 S2）；合并、删除等 S3 重操作永远只在你的电脑上。手机暂时离开，也不打断执行。
你
它会替我 push 代码或开 PR 吗？
说
不会。它只在你项目里的独立 worktree 和 saydo/<任务> 分支上改代码；合并到你的分支要你用本机认证确认或自己动手；推送远端、开 PR 永远是你之后自己做的事。
