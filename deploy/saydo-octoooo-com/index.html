一个完整的闭环

你只管聊和拍板，重活它来。执行和检查都跑完，它主动叫你验收——办完了才算交付。

1

开口聊

按住说话，想到哪说到哪。随口一句「帮我记一下」立刻进账。它会带着对你项目的理解，像采访一样一次问一个，把事聊透。

2

就绪决断

它判断火候够了，主动提议开工——而不是让你凭空写一份完整的需求规格。规格是它的产物，不是你的输入。

3

决策包

端出三件套请你拍板：成果预览（做完你会得到什么）、实施计划（每步标好 AI 执行还是需要你配合）、轻量 Demo（最终长什么样）。

4

你拍板

看着预览和计划说一句「就这样」，它就放手去办。合并、交付，永远是你拍板才算数。

5

后台执行

在你自己的电脑上跑：独立 git worktree 隔离，主工作区不会被碰；有预算、时长、回合熔断，不会无人值守烧钱。你可以走开。

6

办完叫你

执行和检查都跑完，它主动叫你验收——说「等你验收」，而不是「做完了」。该升级通知渠道时，从在线语音回叫一路升到桌面通知、手机推送。

7

验收沉淀

口播摘要加证据视图（diff、测试、决策），按验收标准组织好。你点头，办完盖章销账；知识与产物留存，下次接着用。

不是又一个语音工具

市面上每一块都有成熟单点，但还没人把「聊透、自动开工、办完交付」做成同一套闭环。说到做的是完整治理，不是单点。

AI 真的在干活

接上你电脑上已有的 AI——Claude Code、Codex、Cursor、Grok、Gemini CLI、Qwen Code、GitHub Copilot CLI，更多接入中，无需额外付费。对话、整理、跟进、动手都由它来。

数据完全在你手里

没有云端服务器，没有账号注册。手机扫码连你自己的电脑，数据只在你的设备和局域网里，开发者无法访问、也不收集。

跨设备同一本账

手机上说的，电脑上看得见；电脑里记的，手机上盯得住。沟通天然是移动的，执行天然是固定的。

先吃透，再办事

第一次聊一个项目，先深度研究透、沉淀成持久知识底座。这是「说到」和「新开一个聊天窗口」的分水岭。

沟通面 ↔ 执行面

手机说话，电脑办事

沟通天然是移动的，执行天然是固定的。手机只做沟通——说话、看进展、拍板、审批；重活留在你的电脑上。

沟通面 · 你的手机

说话、看进展、拍板、审批。随时在手，断了也不影响后端。

执行面 · 你的电脑

吃透项目、驱动 AI、后台办事、留存记忆。手机暂时离开，也不打断执行。

隐私至上，本地优先

不运营任何服务器

你的对话、语音、事项与账本数据，全部保存在你自己的设备上，在你自己的局域网内传输。没有账号体系，不埋点，不接入第三方统计或广告 SDK。开发者无法访问、也不收集你的任何数据。

常见问题

先说清楚它不是什么

这是语音输入法吗？
不是。它不做「语音转文字再粘贴」，而是先吃透你的项目上下文，把每件事记成一本账，听懂了主动提议开工、自己把事办成。核心竞争力不在用哪个模型，而在上下文工程和人机协作流程。
是把我的项目上传到云端代跑吗？
不是。没有云端服务器。重活在你自己的电脑上跑，手机只在局域网里和它说话。你接入的第三方 AI（CLI 订阅或 API key）由你的电脑直接调用，开发者不经手、不可见。
需要什么前提？
在你的电脑（macOS）上运行「说到」桌面服务（开源免费），手机扫码即连。AI 用 Claude Code、Codex、Cursor、Grok、Gemini CLI、Qwen Code、GitHub Copilot CLI，更多接入中——已订阅哪家就用哪家，无需额外付费。语音无需额外配置，浏览器即可用。
我的数据存在哪？
全部在你自己的设备上。对话、语音、事项与账本都存在你的电脑里；手机与电脑之间在你的局域网内通信，凭一次性扫码交换的令牌鉴权。删除应用即删除手机端本地数据，电脑端由你自行管理。
它怎么知道「办完了」？
执行和检查都跑完，它会说「等你验收」——而不是「做完了」。它把成果按验收标准组织好（diff、测试、决策），你点头才算办完盖章销账。合并、交付，永远是你拍板才算数。
