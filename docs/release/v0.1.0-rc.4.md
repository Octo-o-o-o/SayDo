# SayDo CLI 0.1.0-rc.4

这是面向 macOS、Windows 与 Linux 的预发布快速启动包。无需克隆源码，安装 Node.js 22 后运行：

```sh
npm exec --yes --package=https://github.com/Octo-o-o-o/SayDo/releases/download/v0.1.0-rc.4/saydo-cli-0.1.0-rc.4.tgz -- saydo up
```

经常使用时可安装到自己的 npm 全局目录，再直接运行：

```sh
npm install --global https://github.com/Octo-o-o-o/SayDo/releases/download/v0.1.0-rc.4/saydo-cli-0.1.0-rc.4.tgz
saydo up
```

本候选替代未创建 Release 的 rc.3：仓库现在用 `.gitattributes` 将 Git 文本 checkout 固定为 LF，避免 Windows `core.autocrlf` 改写法务文件与构建输入；该合同也纳入 CLI 的 source revision。Linux 终止进程组时，agent、BYOA 与受管命令只在已有权威结果或已进入收口时忽略 `ECONNRESET`，活动期 pipe 错误仍会失败并留下有界诊断，也不会误走网络重试；runtime wrapper 明确丢弃的 stdio 与 permit 控制 pipe 则在统一 spawn 边界消费读写端错误，业务结果继续只认 child exit/close。rc.3 标签与首次失败 Actions 记录继续保留，按发布纪律不移动、不重跑。

当前包包含 SayDo daemon 与 Web 控制台。语音 pipeline、系统常驻服务及移动端生产配对不在这个包内；Windows 与 Linux 当前以前台方式运行。

Release 同时附带 `SHA256SUMS` 与包含源码输入摘要的 `release-metadata.json`。三项 exact-set 的 filename、bytes、sha256（tgz 另含 npmIntegrity/entryCount）以及 sourceRevision/buildId/protocolVersion 冻结在仓内 tracked manifest [`v0.1.0-rc.4-assets.json`](v0.1.0-rc.4-assets.json)；该文件本身不是 Release asset。公开 tag 推送前要求 `release.yml` 对该 tag 全历史为零次 push run，并存在禁止 delete/update、无 bypass 的 active tag ruleset；workflow 全历史恰好一次且 `run_attempt=1`，并在开始、创建 Release 前、以及把 Release 标题改成版本名之前重读远端 tag SHA。availability 文案与证据/审计包按同一事务写入；Pages 先 preview 后 production。该标签由干净的公开仓快照构建；发布前在三个桌面系统通过源码绑定分发验收，发布后再从固定 URL 以空 npm cache、空全局 prefix、空 `SAYDO_HOME` 真实安装、启动、访问、停止并检查无 daemon 孤儿。本页描述的是发布候选合同，不是对外放行声明。
