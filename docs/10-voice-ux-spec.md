## 1. 人格与全局口播纪律

- 人格:**幕僚长**——简短、口语、中文;不念代码;先结论后细节。
- **状态词红线**(违者算 bug):runner 退出**不播报**;闸门+产物 settle 后说"**执行和检查都跑完了,等你验收**";合并/交付后才说"**交付了**"。执行状态禁用"做完了/完成了"。
- **时长纪律(双轨)**:**执行任务**不预估剩余,只说已发生("跑了 18 分钟");**奠基/学习类系统自身进度允许粗粒度预估**("大概还要一两分钟",02 §3 透明要求)。
- 数字纪律:成本 unknown 说"还没有确切数字",**不说 0**;金额带单位("元")。
- **TTS 脱敏(安全红线)**:token、secret、客户数据、完整本机路径**永不进 TTS**——统一走一个带 data-class redaction 的序列化层(审批播报与溯源共用),路径说"某个配置文件"、密钥说"一处凭据"。
- 工具调用过渡语:"稍等,我整理一下 / 我记一下"(仅用于超过首响阈值、用户可感知的等待)。
- 口播 ≤ 30 秒(用户主动索取的走读同限);清单 > 3 项转屏幕;选项一次最多念 3 个(4–5 个时念前 3 + "还有两个放屏幕上了")。
- **话术变体三档纪律(M6/②-3;防"照抄源"被执行成逐字 IVR,又防授权/状态类被自由发挥)**:① **锁定**——spokenForm(renderSpoken 渲染)、状态词、中性模式问句、审批封闭肯定词表:逐字,不得变体;② **结构锁定表层可变**——高频句(如 #10/#15)骨架固定、同义表层允许变体;③ **自由池**——应答/承接词("嗯/好/收到")轮换,禁连续两轮同词开头。golden 按档断言(锁定档字面命中、自由池档反连续同词)。

通用归属问题“新事情，还是接着哪个项目继续？”在同一 live session 最多播一次；daemon
须先落 durable `reserved`，TTS enqueue 成功后再落 `asked`，失败落
`enqueue_failed` 并允许后续重试；重建时孤立 `reserved` 为守住“不重复问”而保守阻断，
只有明确 `enqueue_failed` 才重新开放，不能把离线失败冒充用户已听。归属状态分为
`unasked_draft`、`asked_unresolved`、`anchored`；只有未锚定前两态适用本问句，
`anchored` 状态下 Brain 误出的归属问句一律拦截并改播“当前对话已经挂在一个项目上了。
请继续说这件事。”，不得再索路。仍未归属的 draft
首轮由 daemon 直接签发锁定句，不让 Brain 自由改写；输出闸仍按“还是/或者/要么”等
二选一结构识别两侧的“新建/另建/从头”与“继续/沿用/旧有/原先”语义，并要求出现
项目/事情/任务/需求/工程/仓库/代码库/工作区等归属对象及疑问标点或明确询问框架；
疑问证据必须绑定同一句内的 choice window，或绑定“前句一侧 + 后句以 choice connector
开头的另一侧”相邻窗口，不能借完整输出中另一个无关问号背书；无标点询问框架须完整匹配
该窗口；connector 两侧必须各自完整匹配受限的“新建分支”或“续接分支”，且恰好一新一旧，
不能只凭整句尾词猜测分支结束。“沿用旧仓库之前先看成本够不够？”一类嵌套陈述/问句不得
借句尾问号误拦，“沿用原先的/接着之前的”省略表达仍算续接分支。“新仓库还是旧仓库都可以”
一类陈述不得误拦。该判断必须
在截断、分句和播放前针对 provider 返回的完整模型原文执行，跨句或问题落在口播截断范围
之后仍要整体替换为 daemon 锁定句，不能让两个半句或截断位置绕过。
未锚定且当前轮只有单一、正向归属路径时绝不播该问题，而是先机械路由或询问类型；
否定、比较、多个路径或路径任务载荷不视为归属路径。已问后若 Brain
仍生成同句：当前轮无路径时改播“我先按新事情继续。要接已有项目，请直接说本地路径。”；
当前轮已有合法归属路径时绝不再索路，daemon 先机械路由 exact 已登记路径进入归属确认，新路径
缺类型时改播“我已经收到本地路径，但还需要知道这是写作、开发还是其他类型。”

### 2.5 审批确认封闭肯定词表(M6/④-G2;审批级 utterance P0 防线)

定档 sauc **不回 confidence**(工程 ADR-101),而 S2 放行依赖语音确认——ASR 幻觉可凭空产出肯定词、把没说的"好"塞进审批。P0 话术层防线(状态机侧在 3.4/4.2 消费**同一词表**,单源):

1. **确认文法**:S2 确认播报必须**复述关键参数**(任务 + 效果 + 目标,来自 E2 spokenForm),要求用户答复中**包含封闭肯定词表命中项**才算 accept。**适用范围(评审 B-9)**:一切以语音消费的 S2 级收据裁决——运行中 S2(#19/#39)**与携 S2 grants 的预授权清单确认(#12)**;模式问句、纯 S1 拍板对话不在词表制内;
2. **封闭肯定词表**(锁定档,逐字):`好 / 好的 / 可以 / 行 / 批准 / 同意 / 确认 / 通过 / 去吧 / 可以的`;否定表:`不 / 不行 / 不要 / 别 / 取消 / 算了 / 停`;
3. **未匹配默认拒绝并复读**:用户答复既不命中肯定也不命中否定(含空/杂音/无关话)⇒ **默认拒绝**(不放行)+ 复读一次确认播报;连续两次未匹配 ⇒ 转屏幕确认。**收据语义(评审 B-8)**:未匹配**不裁决收据**(receipt 保持 pending),复读 = 绑同一 receipt 的**新 presentation**(新 sentenceId/nonce,A8)，但必须先保持 invalidated，只有新确认句被在线 TTS 入口确认 enqueue 后才 arm；enqueue 失败或抛错时后续裸肯定仍不得消费。转屏后原 voice 收据按超时档终局(09 §3);
4. **否定优先**:同一答复同时含肯定与否定词 ⇒ 判否定(fail-safe;"行"⊂"不行"的词表重叠由此消解);
5. **匹配细则(机械封闭文法,2026-07-25 评审 A1 定稿;fail-safe 方向:误拒可接受——用户重说一次;误放不可接受)**:① 疑问句护栏——以"吗/呢/?/?"收尾 ⇒ unmatched(反问不是批准);② 否定优先——否定词(含单字"不")**任意位置子串**命中即 reject("确认不了/不错"都 reject,宁误拒);③ 肯定 = **整句封闭匹配**"(语气引导词)* + (肯定词)+ + (语气尾)*"——肯定词后跟任何实义内容(如"好几个问题要先问你/没必要说好")一律 unmatched,不做自由子串;
6. **S3 不适用本词表**:S3 语音永不放行,只走屏幕强认证(04 §5.1,红线不动)。

## 3. 轮次与打断规则

1. 轮次三层:VAD → 语义 EOU(~~P1~~ **已提前**,05 §4 提前批 #6)→ 显式按钮兜底;中英混说默认延长静音阈值。

6. 仲裁:会议软件占麦 ⇒ 不出声走通知;会话中新事件不插播,收尾带一句。
7. **桌面采集交互(R-A 2026-07-26 场次①;双动作改版 2026-07-28 owner dogfood 拍板)**:桌面端手动采集提供两种触发(参考微信桌面端语音),与免手档并列共三种:① **点击-再点击**(toggle:点麦克风开始录)② **键盘长按**(按住空格录)③ **免手 VAD**(§3-1 三层,静音自动断轮)。①②统称手动档,contracts 层 `voice.mode` 仍二值(`ptt` 涵盖 toggle/hold / `hands_free`),UI 变体不进 09。**录制中必须有反馈**(实时电平 + 计时 + 可取消区,防"卡住"感)。**录完双动作二选一(owner 拍板)**:「**直接发送**」= 主路径——语音气泡先行进对话(转写异步补挂,AI 即刻开跑;松开空格同义);「**转文字改一改**」= 纠错通道——转写只进输入框(AI 看不到),改字发送才进对话;「取消」= 彻底丢弃零痕迹(hold 语义,不进对话事实)。**异步反馈纪律:转写在途必须有显式"转写中"状态(气泡占位或输入框提示),禁止任何静默等待**;空转写/超时给"没听清"反馈。免手档 = 天然直发。UI 见 11 §5.10;轮次守恒合同见 09 §10。
8. **文本慢速/无语音降级(T18b)**:`dialog_cli_oneshot` 只承诺文本能力,不伪装实时语音环;轮次等待由 UI 定时状态承担,不是 Brain 回复。probe 表明 ASR 未配置/不可用时,麦克风按钮必须在动作前禁用并给人话“语音未配置(可选)——用键盘上的话筒,或直接打字;配好豆包 key 后这里可以开口即说”;键盘系统听写与文本发送始终保留,不得静默失败。
