# 横切:全过程产物持久化 + 随时召回续用(Artifact Store)

> 状态:主方案 v1.4 **部分覆盖但零散**——有 SQLite 执行记录、事件 JSONL、§4.15 结束导出、§4.1 预研 Library,但没有一个贯穿全程的统一产物库。这是让场景 2、3 成立的地基。

## 用户原话诉求

> "在沟通的全过程,如果有新的产物,包括**新生成的产物**和**新调研的产物**,是否都有持久化的保存,方便 AI 和用户随时去 context 里找到内容来继续使用。"

## 拆解

两类产物,都要全程持久化,且要能被"随时召回注入 context":

1. **新生成的产物**:对话中 AI 产出的东西——一版架构草图、PRD 初稿、被否掉的方案 B、一段决策理由、agent 产出的 diff/报告。
2. **新调研的产物**:系统抓来的外部信息——竞品资料、检索结果、数据表、参考文档。

"随时召回"= 用户或 AI 在**后续任意一轮对话**里,能定位到之前的产物并拿回来继续用("上周那版架构""调研里关于定价那段")。

## 目标设计:统一产物库(Artifact Store)

一个贯穿全程的产物库,取代"结束时才导出"的零散做法。每个产物一条记录:

| 字段 | 说明 |
|---|---|
| id | 稳定标识,可被对话引用 |
| project_id | 归属项目(见场景 2/3 的"项目"层级) |
| type | doc / prd / architecture / plan / research-material / dataset / decision / code-diff / report / transcript / … |
| source | 来源:对话生成 / agent 产出 / 调研抓取 / 用户上传 |
| version | 同一逻辑产物的多版本(架构 v1→v2→v3) |
| tags | 主题标签,支持检索 |
| body / pointer | 内容本身或指向文件(大文件存盘,库里存指针) |
| created_at / by | 时间戳 + 产生者(哪次会话/哪个 agent) |

关键能力:

1. **全程写入**,不是结束才存:对话里生成一版方案立即落库;调研抓到资料立即落库;agent 产出实时归档。
2. **可检索**:按项目/类型/标签/关键词/时间。
3. **可召回注入 context**:与 Context Pack(§4.1)打通——新会话开场可注入"本项目相关产物索引",AI 能主动说"我们有一版架构在这";用户也能语音点名调取。
4. **可在控制台浏览**:产物列表/时间线/版本对比,用户随时翻看。
5. **可导出**:任意子集导出为文件交付。
6. **是统一记忆层**:把 §4.1 预研缓存/Library、§4.5 摘要、§4.15 沉淀、事件流统一到这一层,不再各存各的。

## 能力要求 checklist(拿来对账主方案)

- [ ] 统一 `artifacts` 表 / 产物库(而非分散在 events/notes/library)
- [ ] 产物**全程写入**(生成即存、抓取即存、产出即存)
- [ ] 产物**版本化**(尤其文档/方案的多轮修订)
- [ ] 产物**可检索 + 可召回注入 Context Pack**
- [ ] 控制台可浏览产物时间线与版本
- [ ] 与项目层级绑定(每个产物属于某项目)
- [ ] 与预研 Library / 摘要 / 沉淀导出打通为同一层
- [ ] 隐私:产物含敏感信息时的本地存储与不外泄边界

## 验收标准

任一场景下,跨多次会话/多天,用户或 AI 都能定位并取回此前任意产物(含历史版本)继续使用;新会话开场系统能带着"本项目已有哪些产物"的记忆。

## 与主方案的差异 / gap(驱动 v1.5)

把散落的持久化(events/JSONL/notes/library)收敛成一个**一等的、贯穿全程的产物库**,并成为 Context 系统的核心记忆层;§4.10 数据模型需新增 `projects` 与 `artifacts` 两张表;§4.1 Context Pack 与 §4.15 沉淀都改为读写这个库。
