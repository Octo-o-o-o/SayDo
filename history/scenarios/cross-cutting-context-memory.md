# 横切:上下文与记忆架构(对话路径 × 广义上下文)

> 状态:用户 2026-07-22 提出的核心洞察,主方案 v1.6 据此新增 §4.19,v1.7 落定 5 项决策(见 §9)。本文件忠实记录洞察 + 深挖设计 + 已拍板决策(供交叉 review)。
> 与 `cross-cutting-artifact-persistence.md` 的关系:那份讲"产物都要存下来"(存储),这份讲"上下文如何分层、如何奠基、如何按路径装配、如何生长"(架构)。产物库是本架构的存储实现之一。

## 1. 用户原话洞察(忠实记录)

- 用户使用有**两条路径**:① 新对话 ② 接着之前的对话(续接)。
- 新对话又分两种:①a 在**已有项目**(对话过的项目)里开新对话;①b **全新项目**的新对话。
- 这三种情况**最大的不同是上下文如何准备、如何拼接**。
- 对全新项目:用户第一次聊之前,大模型应该有一个步骤**去准备足够的上下文作为沉淀**。
- 这个上下文是**广义的**——不光是 Context Window 里的,还有些应**持久化在本地文件**里。
- 它指的是**以后所有对话都能用到的上下文**,而不是每次提问时才传的上下文。
- 只有提前准备好,后续对话才通畅、有价值;**没准备好 = 和 ChatGPT 新窗口语音聊天没区别**。
- 只有根据项目/对话准备好上下文,并且**把后续每次沟通新生成、新调研的上下文都积累下来**,形成一个**"这个对话/项目的知识库"**,持续对话才对人和 AI 都有启发。

## 2. 深挖:分层记忆模型(Memory Tiers)

用户其实在描述一套**记忆分层**架构。关键是区分"**持久知识库**"(以后所有对话都用得到)与"**每次拼接的 Context Pack**"(单次请求传的)——用户精准点出了这个区分。

| 层 | 名称 | 存储 | 生命周期 | 内容 | 类比 |
|---|---|---|---|---|---|
| L0 | 用户档案 User Profile | 全局本地文件 | 跨项目、长期 | 偏好、常用技术栈、编码/沟通风格、术语热词 | 关于"你"的长期记忆 |
| L1 | 项目知识底座 Knowledge Base | 项目本地文件 `.voiceloop/knowledge/` | 项目级、长期、稳定 | 目标/背景/约束、代码库理解(架构/模块/术语)、关键决策、领域知识、文档体系 | 关于"这个项目"的长期记忆 |
| L2 | 累积对话知识 Accumulated | 项目产物库 `artifacts` | 项目级、随对话增长 | 每次对话新生成的方案/决策、新调研的资料;定期提炼进 L1 | 情景记忆(发生过什么) |
| L3 | 会话工作记忆 Session | Context Window + 转写 | 单次会话 | 当前对话最近 N 轮、当前任务 | 工作记忆(此刻) |

**每次建会话注入的 Context Pack ≠ 知识库**。Context Pack = 检索器从 L0+L1+L2 里挑相关的 + L3,拼进 Window。知识库是持久的大底座,Context Pack 是每次临时取用的小切片。用户说的"以后所有对话可以用到的上下文"= L1/L2;"每次提问传的"= Context Pack。**这是本架构的核心区分。**

## 3. 深挖:项目奠基(Project Bootstrapping)—— 分水岭动作

全新项目首次对话时,执行一次**重投入的奠基**,建立 L1 知识底座:

- `coding`:深度扫代码库 → 架构、模块清单、依赖、约定、术语表、关键文件索引、README/docs 消化;
- `planning`:确立目标/背景/相关方/成功标准,初步竞品与可行性调研(其产出的文档体系本身就沉淀为 L1);
- `research`:领域背景、已知资料、信息源。

产物是**人类可读的本地文件 + 检索索引**,一次性建成、长期复用,而不是每次聊都重做。

> **奠基的有无 = "有价值的持续对话" vs "ChatGPT 新窗口"的分水岭。** 这是用户洞察的核心。此前主方案 §4.1 的"Context 预研器"是它的雏形,但被定位成"每次会话前的轻量预研",没区分"一次性重奠基"与"每次轻预热"。v1.6 拆成两级。

**预研两级:**
- **项目奠基(一次性,重)**:全新项目首次触发,产出持久化 L1。
- **会话预热(每次,轻)**:基于已有 L1 + 本次话题做增量准备(含代码库变更的增量刷新)。

## 4. 深挖:三条路径的上下文装配

| 路径 | L1 状态 | 装配策略 |
|---|---|---|
| ①b 全新项目 | 无 | **触发奠基**建 L1 → 首次 Context Pack = L0 + 新建 L1 + L3 |
| ①a 已有项目·新对话 | 已存在 | 加载 L1 + **增量刷新**(代码变更则更新受影响部分)+ 按话题从 L2 检索 → Pack = L0+L1切片+L2相关+L3 |
| ② 续接对话 | 已存在 | 加载该会话 L3 完整历史 + L1 + 相关 L2 → 无缝续接;结束时把新增沉淀回 L2/L1 |

## 5. 深挖:知识库的生长与维护闭环

只 append 会膨胀且陈旧,需闭环:

1. **生长**:每次对话/agent run 的新产物 → 写入 L2(即产物库);
2. **提炼(蒸馏)**:会话结束或定期,把 L2 里稳定且重要的内容提炼进 L1(如新确认的架构决策更新 `architecture.md`/`decisions.md`)——防 L1 陈旧、防 L2 无限膨胀;
3. **失效/更新**:代码库变更 → 标记 L1 中受影响的代码理解过期 → 下次奠基/预热用 `git diff` 增量重建;
4. **索引**:L1/L2 建轻量检索索引(关键词 + 可选 embedding)供 Context Pack 检索;
5. **人可编辑**:L1 是本地 Markdown,人可直接改(纠正 AI 的理解),AI 尊重人的修改——"对人和 AI 都有启发"是双向的。

## 6. 本地文件形态(建议)

```
<repo>/.voiceloop/
  knowledge/                # L1 项目知识底座(人类可读、可 git 版本化)
    project.md              # 目标/背景/约束/成功标准
    architecture.md         # 代码库理解(coding)/技术架构(planning)
    glossary.md             # 术语表(兼作 ASR 热词源)
    decisions.md            # 关键决策日志(append + 提炼)
    domain/                 # 领域知识、调研沉淀(research/planning)
    index.json              # 检索索引(关键词/embedding 指针)
  artifacts/                # L2 累积产物(方案多版本、调研资料、report、diff…)
  sessions/                 # L3 各会话转写
```
（`~/.voiceloop/profile.md` = L0 用户档案,跨项目）

## 7. 这套架构如何逐句回应用户

- "全新项目第一次聊前有个准备上下文的步骤" → §3 项目奠基(路径 ①b)。
- "广义上下文,不光 Window,也持久化本地文件" → L1/L2 本地文件 vs L3 Window(§2)。
- "以后所有对话都能用到,不是每次提问传的" → L1/L2 是持久知识库,Context Pack 才是每次传的(§2 核心区分)。
- "没准备好 = ChatGPT 新窗口" → 奠基是分水岭(§3)。
- "把后续每次新生成+新调研的都积累 = 对话的知识库" → L2 生长 + 提炼进 L1(§5)。
- "对人和 AI 都有启发" → 人可读可编辑的本地知识库,双向(§5.5)。

## 9. 开放问题 → 已由用户拍板(2026-07-22)
