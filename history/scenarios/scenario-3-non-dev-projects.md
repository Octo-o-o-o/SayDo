# 场景 3:非开发项目(调研 / 营销 / 各类),产出是任务计划而非开发计划

> 状态:主方案 v1.4 **基本未覆盖**——整套设计假设产出是代码。这是本轮完善揭示的最大范围问题。

## 一句话

用户要做的根本不是开发项目,而是一次市场调研、一个营销活动策划、一份行业分析、一套内容生产……最终产出是**这类任务的计划与产物**(报告、方案、行动清单、内容),而不是代码或 PR。

## 角色与前提

- **主角**:研究员 / 市场 / 运营 / 创始人 / 任何知识工作者。
- **前提**:目标是产出"信息/方案/内容",衡量标准是内容质量,而非"测试通过/可合并"。

## 期望完整流程(以"市场调研"为例)

1. 开麦:"帮我做一份关于 2026 年 X 赛道的市场调研,重点看竞品和定价。"
2. 采访澄清:范围、深度、交付形式(一页摘要?完整报告?给谁看?)、时限。
3. **执行调研**:系统调 agent 联网检索、抓取资料、整理数据、交叉印证——过程产生大量**调研中间产物**(原始资料、竞品清单、数据表),全部落库。
4. 产出**任务计划**(不是开发计划):调研报告大纲 / 营销方案框架 / 执行步骤 + 时间表 + 分工建议。
5. 用户审阅、修订。
6. 批准后**执行非编码任务**:生成报告、生成内容、做分析;或输出一份可交给人/团队执行的行动计划。
7. 回叫验收:验的是"报告扎不扎实、方案靠不靠谱",可要求补充/重做某一部分。

## 各项目类型举例(说明"产出多样")

| 项目类型 | 最终产出 | 执行手段 |
|---|---|---|
| 市场/行业调研 | 调研报告 + 资料库 | 联网检索 + 分析 agent(如 RFWG 类 skill) |
| 营销活动策划 | 方案 + 内容日历 + 素材 | 文案/创意生成 + 排期 |
| 竞品分析 | 对比矩阵 + 结论 | 抓取 + 结构化对比 |
| 内容生产 | 系列文章/脚本 | 生成 + 迭代 |
| 编码开发 | 代码 / PR | coding agent(场景 1/2) |

**编码只是项目类型之一**,不是全部。

## 全程产物(应持久化)

调研原始资料、竞品/数据表、分析中间结论、报告/方案(多版本)、行动计划、被否掉的方案、会话转写。

## 能力要求 checklist(拿来对账主方案)

- [ ] **项目类型抽象**:coding / research / marketing / planning / general,不同类型走不同产出与验收模板
- [ ] **产出类型不止代码**:报告、方案、计划、内容、资料库都是一等产物
- [ ] **执行 agent 不止 coding agent**:能接通用/调研能力(Claude Code/Codex/Cursor 本身也能写文档做调研;或接 RFWG 类 skill / 通用 agent)
- [ ] **验收标准可切换**:内容质量评审替代"跑测试";verify(测试)对内容项目不适用
- [ ] **隔离/版本化对内容项目适配**:一个 project 目录 + 文件产物 + git 版本化(worktree 对纯内容可选)
- [ ] **"任务计划"作为产出**:可导出、可执行、可跟踪
- [x] 上游能力(采访、Context/调研预研、回叫、摘要、产物沉淀)本身是通用的,可复用

## 验收标准

对一个明确的非编码项目(如"某赛道市场调研"),能走通"对话澄清 → 调研/执行 → 产出报告或方案 → 语音验收修订",且全程产物可查可续用。

## 与主方案的差异 / gap(驱动 v1.5)

主方案需从"编码开发工具"升级为"**对话驱动的通用项目协作/执行工具**":引入项目类型与产出类型抽象;把 worktree/verify/PR 这些从"硬编码假设"降为"coding 类型的具体实现",其它类型有各自的执行与验收实现;适配层扩展到非编码 agent/能力。
